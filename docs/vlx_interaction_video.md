# VLX 录像拿起 / 放下统计

入口：`scripts/run_vlx_interaction_video.py`。这是独立的后端录像分析功能，
目前输出文件，前端接入和数据库写入留到后续。运行时不加载会员资料。

## 固定物品

每个名称对应一个具体物品实例：橙色卡通玩偶、白色蛋形玩偶、粉色毛绒玩偶、
黄色机器狗、白色电吉他、小蜜蜂玩偶。目标表定义在
`agent/vlx_interaction.py` 的 `TARGETS`，英文短语用于 VLX 定位。
同类出现多个不同候选时暂不判断其动作，不能把多个实例合并成一个物品。

## 运行

在项目根目录 PowerShell 中执行环境检查（不加载模型）：

```powershell
& D:/project/RetailVisionDev/envs/vlx-interaction-py311/Scripts/python.exe scripts/run_vlx_interaction_video.py --check
```

准备好测试录像后运行：

```powershell
& D:/project/RetailVisionDev/envs/vlx-interaction-py311/Scripts/python.exe scripts/run_vlx_interaction_video.py --video 'C:/path/to/recording.mp4'
```

可选参数：`--output-dir` 指定一个尚不存在的结果目录；`--no-preview` 仅输出
JSON / JSONL。默认结果目录位于
`D:/project/RetailVisionDev/runtime/vlx-interaction-video/<运行时间>/`。
已有结果目录会被拒绝，不覆盖历史结果。失败记录也保留在该次目录。
建议测试使用未叠加旧模型框、文字的原始录像，避免覆盖物品细节。

录像分析环境 `vlx-interaction-py311` 复用本机 `vlx-seek-py311` 的模型依赖，
单独安装 `opencv-contrib-python==5.0.0.93`，提供 CSRT 跟踪；原实时预览环境未替换。
缺少 CSRT 时，默认配置会明确报错，不会悄悄退回较弱的跟踪后仍声称使用修复版。

## 处理方式与口径

1. ffprobe 读取每帧原始 PTS，OpenCV 顺序解码；默认至多每秒分析 5 帧，
   最后一帧也进入分析。模型处理速度不会改变视频内动作时长。
2. WeDetect 自动产生候选框，VLX-Seek 选择六件物品。默认每 0.8 秒视频时间
   复核一次，最近可见物品跟踪丢失时提前复核。每个原始帧使用局部光流；
   人物接近物品或光流失效时使用 CSRT 外观跟踪，运动时保留已学习的外观，
   连续稳定的模型框会重新校准它。距真实 VLX 确认最多保留 6 秒，期间仍需
   每帧像素跟踪有效；不是冻结旧框，也不会把跟踪时间冒充模型确认时间。
   同类检测突然跳到别处时，须再有一致模型结果才替换旧轨迹，替换本身不算物品位移。
   模型原始结果、纠正记录和跟踪来源写入逐帧记录。
3. 本机 YOLO11n-pose 仅用于人物与手腕位置，默认 CPU 推理，分析尺寸 1280。
   匿名用户按首次出现顺序编号；同时首次出现按画面从左到右编号。
   同一视频内通过位置、运动和衣着外观维持编号；短时失踪及重入保留候选关联。
   有多个同样合理的匹配时显示“用户关联不确定”，不强行分配操作归属。
4. 物品先在没有附近手部证据时建立稳定起点；随后发生位移、唯一用户手腕靠近，
   且手与物品同向移动持续得到确认，才记录一次拿起。默认确认窗口 0.4 秒。
   位移使用两侧边界共同移动的部分，避免整件物品与局部框之间切换造成中心点假运动。
   双手曾同时接触同一物品时分别保存证据；一旦拿起进入确认，则固定使用该只手。
5. 拿着不动继续计时；抛起后接住仍算同一次持有。物品持续稳定、原用户两只手腕均可见且远离物品、
   附近没有其他手部或遮挡导致的未知接触证据，持续 0.8 秒才确认放下。
   放置地点不受桌面区域或原始位置限制。放下后可从新位置开始下一次操作。
   另一条放下证据是持续返回本视频已观察到的放置姿态：物品底部与水平占用区域
   匹配、位置持续稳定 0.8 秒，允许手仍贴近物品；放下确认后重新准备下一次拿起。
   这是二维视觉估计，不能严格区分贴近支撑面悬停和真实承托。
6. 事件时间记录持续确认窗口的起点，同时单独记录确认时间。
   持有时长 = 放下时间点 - 拿起时间点；此版不统计两次操作间的放置时长。
7. 已观察到稳定起点和手部接触后，快速移动造成的短暂断跟踪可保留拿起候选。
   恢复需要同一用户的同一只手、手和物品方向及位移相符；未知手腕不被另一只手替代。
   物品必须在手部接触之后继续发生位移，避免把接触前的框变化误当成拿起。
   没有接触证据的间隔不累计确认时间，恢复首帧不能直接确认拿起。候选受 2 秒宽限约束。
   同一放置区域的重叠局部框可以保留已观察到的接触，但局部框本身不能证明拿起。
   尚未看到拿起起点的接触物品显示“状态待确认”，不宣称已经放置。
8. 短暂遮挡保留会话，恢复首帧不能直接确认放下。返回已知放置姿态时，
   可从首个重新看见的时刻开始累计确认，缺失期间不计入确认窗口。
   物品或用户失踪超过宽限、疑似交接、录像结束仍持有，均记为 `incomplete`。
   不生成虚构放下，不把未完成时长混入已完成持有总时长。
9. 起点丢失后，须持续 0.6 秒匹配最近 30 秒内已观察到的放置姿态，
   才重新准备下一次拿起；仍须再看到接触后的位移和手腕同向运动。
   放置姿态由当前视频自动观察得到，不使用预设桌面或区域；最初就拿在手里的物品
   没有此参考，不补造拿起。相似物品占据同一位置仍可能造成误关联。
   检测器省略触角等上部细节时，可通过底部、水平重叠与尺寸约束匹配参考。
   重复模型纠正之间的原始像素若持续验证该框静止，可用于恢复已知放置起点；
   该证据不能为最初就拿在手里的物品创建起点。

阈值在 `config/vlx_interaction_video.yaml`。距离为归一化画面坐标，不是厘米。
这些是第一版实验参数，尚未通过用户真实操作录像的精度验收。

## 输出

| 文件 | 内容 |
| --- | --- |
| `result.json` | 每次会话、事件、按物品 / 用户 / 用户和物品汇总、用户列表、识别覆盖计数 |
| `events.jsonl` | `PICK_UP`、闭合会话的 `HOLDING`、`PUT_DOWN` |
| `observations.jsonl` | 原视频帧号与时间、物品框、人员和手腕、模型原始输出、判定原因 |
| `annotated.mp4` | 用户编号、物品框、当前状态与计时；不含原音频 |
| `manifest.json` | 原视频 SHA-256、时间信息、配置、目标及模型版本 |
| `status.json` | 加载 / 分析进度 / 完成 / 失败 |
| `partial_result.json` | 仅在失败时输出的未最终完成结果 |

`result.json.sessions` 的主要字段：`object_key`、`object_name`、`user_id`、
`user_label`、`pickup_seconds`、`putdown_seconds`、`holding_seconds`、`status`。
另有 `pickup_confirmed_seconds`、`putdown_confirmed_seconds` 说明确认延迟。
未完成会话的 `holding_seconds` 和 `putdown_seconds` 均为 null；
`observed_holding_seconds` 是截至最后可观测时刻的长度，不代表闭合时长。
短暂缺失通过 `observation_gaps` 标记，疑似用户交接通过 `attribution_uncertain` 标记。
`manifest.json` 和 `result.json` 的 `interaction_policy` 标识动作规则版本；
`tracked_correction_rest_repeat_v6` 保留边界共同位移、独立手部证据和证据断点计数，
新增重复纠正、已知放置姿态返回与再次拿起的处理。单次模型跳框等待复核时，
仍有效的原像素轨迹可继续提供证据；多实例或不同类别争用同一区域时保持不确定。
同一区域的完整框与局部框也参与实例冲突检查，避免同一件物品按两个标签计数。
用户指定的粉色玩偶若对应黄色明显多于粉色的区域，会被标为属性矛盾，
记录在 `appearance_rejections`；颜色检查只否决矛盾标签，不依颜色给物品分类。
暖光、遮挡和相似物品仍会影响此项检查，跨摄像头精度尚未验收。

短暂源录像缺帧恰好跨越失踪宽限时，仅在缺帧前会话尚未过期、间隔不超过
2 秒、同一匿名用户仍可见、物品重新出现在已知放置姿态且没有交接证据的情况下，
保留原会话继续确认放下。`source_gap_return_recoveries` 标记这种恢复；
放下时间仍取重新看见之后的确认起点，不倒填缺帧中的动作时间。

持有中会在物品框旁显示“用户编号 / 已拿起 X.X 秒”，同时保留底部状态汇总。
该时间从本次已确认拿起的事件起点计算，不从物品第一次被框出的时刻开始。

2026-10-28 显示更新：物品旁显示“用户2 | 小蜜蜂玩偶 | 累计拿起2次 |
本次已拿起5.3秒”。右侧按匿名用户和物品分别保留累计拿起/放下次数，
放下后仍保留统计；最近完整记录显示持有时长，未完成记录明确标注。
每帧只读取该时刻的 `by_user_object` 汇总，不提前显示后续动作次数。
记录超过一页时每8秒轮换一页，视频尺寸保持固定。此改动仅涉及视频展示，
识别、匿名关联、拿起/放下规则和 JSON 统计口径不变。

统计中的拿起次数包含已确认但未闭合的会话；放下次数、累计 / 平均 / 最长持有时长
仅使用闭合会话。平均和最长时长没有样本时为 null。没有检出任何操作的物品仍出现在
`by_object` 中；结合 `object_observation_counts` 区分“没有动作”和“物品未被定位”。

标注视频以固定帧率展示，会在相邻真实分析帧间保持画面，时间误差最多一个展示帧。
这些展示帧不参与推理、动作计数或时间计算。原始 VFR 时间戳用于事实计算且被保留。

## 重放已有模型结果

```powershell
& D:/project/RetailVisionDev/envs/vlx-interaction-py311/Scripts/python.exe scripts/replay_vlx_interaction_video.py --recorded-run 'D:/path/to/previous-result' --output-dir 'D:/path/to/new-replay'
```

此命令核对源录像 SHA-256，在原始推理帧上复用保存的 VLX 输出和匿名姿态，
重新计算原始像素跟踪与动作判定。`evidence_provenance` 明确标记
`recorded_model_source_pixel_replay` 与 `fresh_model_inference: false`。
它不重新请求模型，不代表新的模型精度测试；原始产物保持不变。

## 验证与限制

自动化测试包含动作状态、重复操作、多用户归属、静止持有、遮挡、跟踪丢失、
未完成会话、重复时间戳、VFR 时间线，以及生成 MP4 → 注入受控视觉结果 →
导出视频和 JSON 的文件流程。受控视觉结果不是 VLX 识别精度证据。

手腕靠近和二维同向运动只能提供抓取 / 释放的视觉估计：推动物品、身体遮挡、
手腕误检、相似衣服、离开很久再进入、物品严重旋转等仍可能导致漏判或误判。
此版不会确认多人交接，也不提供跨视频身份一致性。
用户提供的旧 SAM3 叠加视频用于了解预期效果，真实六物品动作验收留到后续测试。

## 代码边界

- `agent/vlx_interaction.py`：动作状态、时间口径和结果汇总。
- `agent/vlx_person_tracking.py`：视频内匿名人员关联。
- `scripts/vlx_interaction_vision.py`：VLX / WeDetect / 光流 / 姿态模型适配。
- `scripts/vlx_interaction_tracking.py`：录像专用局部光流与 CSRT 跟踪。
- `scripts/vlx_target_evidence.py`：固定目标属性矛盾与实例占用冲突。
- `scripts/replay_vlx_interaction_video.py`：校验来源后重放原始模型输出。
- `scripts/run_vlx_interaction_video.py`：文件输入、PTS、任务编排和产物导出。

独立实验入口复用既有 VLX 模型加载与光流组件，不改变 SAM3 Stage5/7C/8/9、
正式 Offline V1 事件语义、数据库表或生产发布开关。
